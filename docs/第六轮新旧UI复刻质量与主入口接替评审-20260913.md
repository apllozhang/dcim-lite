# dcim-lite 第六轮新旧 UI 复刻质量与主入口接替评审

> 评审日期：2026-09-13  
> 评审基线：新 UI 镜像对应 `main@2ff888a`，评审材料提交 `234a0e8`  
> 评审入口：`docs/EXPERT-REVIEW-GUIDE-20260913.md`  
> 评审范围：仅评估新 UI 对旧 UI 的观感、版面、行为复刻质量，以及能否接替 19500 主入口；不重复评审前几轮已经裁定的后端和前端基础架构。  
> 数据口径：19502 是测试库；`MTX-`、`DUAL-`、`DBG-` 前缀属于合法 E2E 种子，不作为脏数据问题。  
> 分类纪律：所有意见严格归入“契约差异 / 如实化登记 / 缺陷”；缺陷使用 P0～P2。

## 1. 最终裁定

### 1.1 主入口接替结论

**当前裁定：NO-GO，不批准现在把 19500 从旧 UI 切换为新 UI。**

这个 NO-GO 是一个范围明确、可以在下一轮解除的工程裁定，不代表重建方向失败。新 UI 已经适合继续作为 19502 预览环境，也适合开展受控内部试用；但主入口面对真实用户时，不能出现“按钮存在但点击无效”以及主台账关键信息列消失的情况。

解除 NO-GO 的最低条件：

1. 设备页“批量导入”和“导出设备信息”要么完成真实闭环，要么在产品决策明确延期后从主界面移除并登记差异；不允许继续保留无响应按钮。
2. 恢复旧设备台账的“设备类型、资产编号、管理 IP”关键信息，或提交经产品负责人批准的删减决策与可替代查看路径。
3. 补齐大屏设备“查看详情/编辑设备信息”入口，或证明用户可在不丢失当前上下文的情况下到达等价操作。
4. 对六屏执行一次人工交互验收，覆盖按钮、对话框、筛选、分页、导入导出、返回和错误态；不能只依据静态截图及成功路径 E2E。
5. 修正评审导航中的事实错误和已知未完成清单，使材料与运行实现一致。
6. 完成一次 19500 切换前演练：19502 通过、切换、冒烟、失败回滚到 19501/旧镜像，并留存时长和结果。

完成上述条件后，可改判为 **“有条件 GO：先灰度、再全量”**，不需要重新推倒六屏实现。

### 1.2 总体评价

新 UI 已不再是“工程骨架”，而是具备六个主要业务屏、机柜容量、PDU 管理和机柜图导入导出的自主前端。视觉语言、颜色、字号、间距、卡片、表格和大屏风格已经建立稳定的 ALE 识别度。

综合本轮证据，建议评分：

| 维度 | 分数 | 结论 |
|---|---:|---|
| ALE 视觉风格一致性 | 88/100 | 色板、组件和大屏表现较强，应用壳仍有明显结构差异 |
| 页面布局与信息密度 | 82/100 | 资源、机柜、模板较接近；设备页信息被明显删减 |
| 关键行为复刻 | 72/100 | CRUD 与大屏主链路较丰富，但存在死按钮和已知行为缺口 |
| 差异披露完整性 | 68/100 | 6 条契约差异多数合理，但遗漏了实际可见功能差异 |
| 自动化证据 | 84/100 | 48 单测、矩阵/双跑/E2E 基础良好；缺完整六屏交互矩阵 |
| 主入口接替就绪度 | 76/100 | 已接近可灰度，尚未达到可全量接管 |

**综合复刻质量：约 80/100。** 这是“质量较高但仍有主入口阻断项”，不是“页面尚未成形”。

## 3. 六屏复刻评价

### 3.1 运行概览

**观感：良好。版面：良好。行为：基本可接受。**

- 四个统计卡、开发进度、跳转入口和颜色层次高度接近。
- 新版左侧菜单增加图标，导航辨识度优于旧截图，属于可接受增强。
- 新旧应用壳的顶栏/侧栏结构并不相同：旧 UI 的 logo 占据左上角，平台标题从侧栏右侧开始；新 UI 顶栏横跨全宽，logo 下移到第二行。这是所有普通页面都会看到的系统性差异。
- 导航称“运行概览是新 UI 独有页”，但评审包同时提供了旧 UI 的 01-dashboard 截图，且内容基本对应。该表述与证据冲突。

结论：页面本身可接受；应用壳差异列为 P1，导航表述列为 P1 文档缺陷。

### 3.2 资源层级

**观感：优秀。版面：优秀。行为：从代码和现有测试看基本完整。**

- 三栏级联、统计条、卡片样式、选中态和右侧机柜表格与旧 UI 非常接近。
- 同一数据下，新旧 full-page 高度只差 28 px，说明高数据量场景的密度和排列稳定。
- 已看到数据中心、机房、机柜的新增、编辑、复制、移动、删除处理，以及空态和错误处理。

结论：本屏无主入口阻断项；进入人工验收时重点测试移动/复制后的选中态、删除取消、接口失败后能否继续操作。

### 3.3 设备台账

**观感：良好。版面：不完整。行为：存在主入口阻断。**

与旧截图相比，新设备台账表格缺少：

- 设备类型；
- 资产编号；
- 管理 IP。

这三个字段是设备识别和日常定位所需的高频信息，不能简单视为视觉差异。新表虽然更紧凑，但信息能力下降。截图 full-page 高度从旧版 1806 px 变为新版 1527 px，也印证了展示密度和列结构发生了明显变化。

更严重的是：

- “批量导入”按钮只有 `data-test`，没有点击处理；
- “导出设备信息”按钮没有点击处理；
- 单测只断言“批量导入”文字存在，没有验证点击后产生对话框、下载或明确提示。

这属于典型的“看起来完成、实际上无行为”，必须作为 P0 修复。若第 9 轮前确实不准备实现，也必须隐藏/禁用并明确写“暂未开放”，但这样仍不满足对旧 UI 的完整接替。

### 3.4 机柜管理

**观感：优秀。版面：良好。行为：主体完整。**

- 统计卡、三级筛选、搜索、主表字段、详情抽屉和 U 位入口均已实现。
- 旧 UI 把行操作收在省略号菜单，新 UI 直接显示“详情/编辑/U 位/删除”。功能可达性更好，但视觉密度和误触风险不同。
- 旧版与新版 full-page 高度分别为 2398 px 和 2070 px，新版行高更紧凑。这个差异本身可接受，但需要真实用户确认长表浏览是否更高效。
- 机柜批量导入是 CSV，而旧版是 xlsx。只要模板、校验、错误回执和中文/逗号/换行兼容性经过验证，可作为如实化差异接受；目前文档应明确“机柜已实现 CSV，设备尚未实现”，不能混写。

结论：无 P0；省略号与直接操作的差异建议作为“已批准 UX 增强”登记，不要处于既未复刻又未决策状态。

### 3.5 机柜模板

**观感：优秀。版面：优秀。行为：主体完整。**

- 信息提示、系统标签、表格字段、状态标签和规格信息接近旧 UI。
- 新 UI 直接展示“新版本/编辑/删除”，旧 UI 收在省略号菜单。与机柜页相同，应作为统一 UX 决策处理。
- 系统模板删除禁用、发布新版本、新增与编辑均有实现。

结论：无主入口阻断；人工验收应确认发布版本后当前版本立即更新、旧机柜快照不变、系统模板不可删除或停用。

### 3.6 机房大屏、PDU 与机柜图

**观感：优秀，是本轮复刻最强的一屏。版面：高度一致。行为：主链路丰富但仍有缺口。**

- 深蓝底、青色边框、统计卡、筛选 chips、机柜卡、U 位刻度、设备块和网格背景高度接近。
- 同尺寸截图的整体结构、色板和空间关系接近，已形成可信的 ALE 大屏风格。
- 上架、迁移、下架、机柜新增/编辑/删除/详情、PDU 管理、机柜图 xlsx 导入导出均有源码实现。
- 容量分析对缺字段显示“无法计算+原因”，比伪造 0% 更可信，应保留。
- 已知缺少设备详情/编辑对话框和机柜右键菜单。设备详情/编辑属于高频业务能力，主入口替代前至少要提供等价入口；右键菜单如果工具栏入口已完整，可降级为 P2 交互差异。
- 大屏生产 chunk 501.90 kB，刚好越过告警线。当前不是阻断，但应拆分 xlsx、PDU/详情弹窗等非首屏代码，避免低带宽内网首次加载迟缓。

## 4. “契约差异 / 如实化登记 / 缺陷”三分类

### 4.1 契约差异

| ID | 差异 | 裁定 | 要求 |
|---|---|---|---|
| C-01 | `row/column` ↔ `rackRow/rackColumn` 双向映射 | 接受 | 保持集中映射并补 round-trip 单测，禁止页面各自转换 |
| C-02 | v2 发送 `templateVersionId`，新后端按 `templateId` 取当前版本 | 有条件接受 | UI 必须明确“保存时采用当前版本”；最好让请求带预期 revision，防止选择后发布新版本造成静默漂移 |
| C-03 | 服务端自动编码改为前端 `Date.now()` 编码 | 暂不接受为最终生产方案 | 多用户同毫秒可能碰撞；应由服务端生成，或使用强随机/UUID、唯一冲突自动重试并有测试 |
| C-04 | `u-layout used/devices` 映射自 `positions/free` | 接受 | 属适配层职责，已有统一映射方向正确 |
| C-05 | `REDUNDANT` 映射为后端 `STAND_BY` | 接受 | UI 文案保持“冗余路”，API 枚举保持契约值 |
| C-06 | socket status 从客户端可写改为连接事实维护 | 接受并支持 | 属明确的完整性修复，不应为复刻旧缺陷而回退 |

结论：6 条中 **4 条接受、1 条有条件接受、1 条不接受为最终生产方案**。总表分类思路正确，但不能因此推导“所有差异均已可关闭”。

### 4.2 如实化登记

以下内容可以保留为已知、可接受或延期差异，但必须写清能力状态：

| ID | 项目 | 正确登记方式 |
|---|---|---|
| R-01 | 容量字段不足 | `ACCEPTED_DATA_BOUNDARY`；显示无法计算和缺失原因，不用 0 伪装 |
| R-02 | 机柜批量导入 CSV 替代 xlsx | `IMPLEMENTED_DIFFERENT_FORMAT`；补中文、引号、换行、Excel 打开、错误回执验证 |
| R-03 | 设备批量导入 | `NOT_IMPLEMENTED`；当前按钮是死入口，不能写成“CSV 流程已实现” |
| R-04 | 设备信息导出 | `NOT_IMPLEMENTED`；当前按钮是死入口 |
| R-05 | 大屏设备查看/编辑 | `NOT_IMPLEMENTED`；上架/迁移/下架已实现不等于设备菜单完整 |
| R-06 | 大屏机柜右键菜单 | `NOT_IMPLEMENTED_EQUIVALENT_ENTRY_EXISTS`；已有工具栏入口，可作为 P2 延后 |
| R-07 | 行操作从省略号改为直接文字按钮 | `INTENTIONAL_UX_CHANGE`；需产品确认，并统一机柜/模板/设备页口径 |
| R-08 | 普通页面应用壳结构不同 | `VISUAL_DEVIATION_PENDING`；不是契约差异，应由 UI 负责人裁定是否对齐 |
| R-09 | 运行概览来源 | 修正文档；现有旧 UI 截图证明不是“无 legacy 对应模块” |

因此，当前“已知未完成项”清单**不完整**，至少漏了 R-03、R-04、R-07、R-08、R-09。

### 4.3 缺陷清单

#### UI-P0-01：设备批量导入按钮无行为

- 位置：`frontend/app/src/features/device/DeviceManager.vue`，设备页头“批量导入”。
- 证据：按钮没有 `@click`；没有导入对话框或处理函数；单测只验证文字存在。
- 影响：旧 UI 的显式能力在新主入口不可用，用户点击无反馈。
- 验收：点击打开真实导入流程；模板下载、文件校验、预览、提交、错误回执和取消均可用，并有 E2E。若明确延期，按钮必须移除/禁用并提示，但主入口替代仍需产品签字接受能力降级。

#### UI-P0-02：导出设备信息按钮无行为

- 位置：同上，“导出设备信息”。
- 影响：导出主流程完全不可用且无反馈。
- 验收：下载文件具有正确扩展名、MIME、列集合、中文编码和当前筛选口径；E2E 校验文件而非只校验 download 事件。

#### UI-P1-01：设备主表丢失三列关键信息

- 位置：设备表只渲染编码、名称、状态、高度、位置、操作。
- 对照：旧 UI 截图还包含类型、资产编号、管理 IP。
- 影响：用户无法在主表快速识别资产和网络位置，日常运维效率下降。
- 验收：恢复三列，允许在窄屏通过横向滚动或列显隐保持可用；对缺失值使用统一占位符。

#### UI-P1-02：应用壳的顶栏/侧栏结构未对齐

- 位置：`AppLayout.vue`。
- 影响：六个普通页面都会出现；这是最醒目的产品级差异之一。
- 验收：产品/UI 明确二选一：对齐旧结构，或登记为自主 UI 的批准升级。不能继续声称完全对齐而不记录。

#### UI-P1-03：大屏设备详情与编辑缺失

- 位置：大屏 U 位/设备上下文菜单。
- 影响：用户需要离开当前大屏上下文才能查看或修改设备，不等价于旧流程。
- 验收：补详情和编辑，或提供带返回上下文的显式跳转；权限、保存、取消、冲突错误均有验证。

#### UI-P1-04：前端时间戳自动编码存在并发碰撞风险

- 位置：`rackShared.ts:autoCode()`。
- 影响：多标签页或多个用户在同一毫秒创建同前缀资源会生成相同编码，最终出现 409；刷新重试也可能造成不一致体验。
- 验收：改为服务端生成，或足够随机的客户端编码加冲突重试；新增并发负例测试。

#### UI-P1-05：评审导航存在事实冲突和遗漏

- 位置：导航 §5。
- 问题：称运行概览无 legacy 对应，但提供旧 UI 对照；把设备/机柜 CSV 混写，掩盖设备导入实际未实现；未列设备导出死按钮和三列缺失。
- 验收：导航、截图索引、实现状态和源码逐项一致；为每项增加 `IMPLEMENTED/PARTIAL/NOT_IMPLEMENTED/ACCEPTED_DIFFERENCE` 状态。

#### UI-P2-01：机柜、模板操作呈现方式与旧 UI 不一致

- 旧 UI 使用省略号菜单，新 UI 直接铺开文字操作。
- 建议：如果保留新版方式，登记为 UX 增强并检查删除误触；如果追求像素级一致，则统一恢复菜单。

#### UI-P2-02：大屏机柜右键菜单未实现

- 因编辑、删除已有显式入口，暂不阻断主入口，但应补齐鼠标用户的交互一致性或明确删除该规格。

#### UI-P2-03：大屏首屏包超过 500 kB 警戒线

- 当前构建产物 `RoomScreenView` 为 501.90 kB。
- 建议延迟加载 xlsx 解析、PDU 管理、容量详情和导入对话框；在真实内网环境记录首屏 JS、LCP 和交互可用时间。

#### UI-P2-04：响应式与无障碍证据不足

- 普通页面虽然部分使用响应式列，大屏明确设置 `min-width:1180px`，评审包只提供 1600×900。
- 切换前至少验证 1366×768、1920×1080、125% 缩放；补键盘焦点、Tab 顺序、对话框焦点陷阱、按钮可访问名称和颜色对比检查。

## 5. 第 9 轮生产加固清单复核

现有“口令收口、SSH 密钥登录、IP 白名单”是必要项，但**不完整**。建议至少增加：

### P0：切主入口前必须完成

1. 删除共享测试管理员口令，建立实名管理员账户；首次登录强制改密，禁止仓库、镜像和部署日志出现明文口令。
2. JWT 密钥、数据库口令、监控凭证全部通过密钥管理或受限环境文件注入，并完成轮换演练。
3. 入口启用 HTTPS/TLS；HTTP 强制跳转；确认 Secure/CSP/HSTS/nosniff/frame 等安全头。
4. 管理接口和管理页面同时执行后端 RBAC，不能只依赖前端隐藏菜单。
5. 关闭或限制 5173、19501、19080 等评审/遗留端口的外部访问；明确 19501 仅作为回退源的生命周期。
6. 切换前完成数据库备份与恢复演练、应用版本回滚演练；记录 RTO/RPO 和责任人。
7. 生产部署只允许不可变镜像 digest；保存 SBOM、漏洞扫描和发布审批证据。

### P1：首个生产观察期必须完成

1. 管理员 MFA 或堡垒机二次认证；禁止多人共用 admin。
2. 登录失败、权限拒绝、批量导入、导出、删除、上架、移位、下架等关键动作进入审计日志。
3. 前端错误率、接口 5xx、401/403 激增、页面加载失败、数据库连接池、磁盘和备份失败建立告警。
4. 配置 CSP 并核查 token 存储的 XSS 风险；若继续使用 localStorage bearer token，必须有严格脚本源控制和依赖供应链控制。
5. IP 白名单应在防火墙/反向代理执行，保留应急访问流程，避免误配置后无人可进入。
6. 测试种子与生产数据隔离。生产不得运行 E2E 写用例，测试前缀清理只在测试库执行并留审计。
7. 定义蓝绿/金丝雀指标、观察时间、自动或人工回滚阈值。

## 7. 给 5 个问题的直接答案

### 问题 1：六屏哪些差异可接受、哪些必须改？

- 可接受：资源层级、模板和机房大屏的主体视觉；`u-layout` 适配、`STAND_BY` 映射、socket 状态收权；容量无法计算的诚实显示；已批准后的直接操作按钮和 CSV 机柜导入。
- 必须改：设备导入/导出死按钮、设备表三列缺失、大屏设备详情/编辑缺失、应用壳差异未登记、文档事实冲突、自动编码碰撞风险。

### 问题 2：6 条契约如实化归类是否认可？

不完全认可。C-01/C-04/C-05/C-06 认可；C-02 有条件认可；C-03 不能作为最终生产方案直接关闭。

### 问题 3：已知未完成项是否完整？

不完整。至少缺少设备导入未实现、设备导出未实现、设备表三列缺失、应用壳结构差异、直接操作按钮 UX 差异和运行概览来源表述冲突。

### 问题 4：新 UI 接替 19500 是什么裁定？

**NO-GO。** 19502 可以继续预览和内部试用；完成 §1.1 六项最低条件后，进入“有条件 GO 的灰度接替”，而非立即全量替换。

### 问题 5：第 9 轮加固有无遗漏？

有。除口令、SSH 密钥和 IP 白名单外，还必须加入 TLS、密钥轮换、实名管理员/MFA、后端 RBAC、遗留端口收口、备份恢复、回滚演练、不可变镜像、审计告警、CSP/XSS、生产与 E2E 隔离及灰度阈值。

## 8. 结语

第 6 轮的成果是实质性的：六屏已经形成较高质量的自主 ALE UI，特别是资源层级、机柜模板和机房大屏，已经具备接近旧产品的观感。当前阻止接管主入口的不是整体重做，也不是技术瓶颈，而是少数关键能力未闭环、差异材料没有完全如实以及缺一次完整人工验收。

**最终结论：复刻质量总体良好（约 80/100）；19502 可继续评审和内部试用；19500 主入口当前 NO-GO。优先关闭 2 个 P0、5 个 P1 后，再做一次灰度/回退演练即可重新申请接替裁定。**
